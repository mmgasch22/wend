# WEND Development Rules

## Philosophy

Build a product, not a demo.

Understand before coding.

Finish before expanding.

## Development

- One feature at a time.
- Small commits.
- Every important decision must be documented.
- Simplicity beats cleverness.
- Always understand the code before accepting it.

## Documentation

The repository is the source of truth.

Documentation lives inside `/docs`.

Notion is only used for project management.

## Code Quality

Readable code > short code.

Reusable components when appropriate.

Meaningful variable names.

Avoid premature optimization.

## Learning

Never copy code without understanding it.

If a technology is introduced, understand why it is needed.

Always ask "What problem does this solve?"

## Product

Never add features outside the MVP without documenting why.

User value comes before technical complexity.

Always prioritize finishing.
